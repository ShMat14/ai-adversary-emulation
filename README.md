# Structural action masking for reinforcement-learning adversary emulation

This repository holds the environment, the agents and the result records for a study of
adversary emulation in which action feasibility is enforced *structurally* rather than
learned from a reward penalty. It accompanies a manuscript under review; the manuscript
itself is not published here.

## What is in it

An adversary-emulation environment over a twelve-host, five-zone enterprise estate with
45 MITRE ATT&CK-aligned techniques, giving a 540-action space of (technique, host) pairs.
Every action is gated by its real precondition through a mask computed inside the
environment, verified exhaustively over millions of state-action pairs so that it permits
no infeasible action and blocks no feasible one. Credential material is typed, so
pass-the-hash, pass-the-ticket and an SMB logon consume different stolen material and are
three actions rather than one.

A rule-based defender watches the Windows Security, Sysmon, WAF, PowerShell and auditd
records each technique would leave, so a detection rate decomposes into the named rules
that produced it.

Four algorithms across two families. Two of them had to be written rather than
configured, because no library ships them: `analysis/maskable_dqn.py` masks both the
greedy selection and the bootstrap target, which is what masking a value-based method
actually requires, and `analysis/maskable_a2c.py` applies MaskablePPO's machinery to
A2C's update rule while keeping A2C's own optimiser so the ablation isolates the mask.

## Layout

| Path | What it holds |
|---|---|
| `env/` | the world model, the estates, the technique catalogue, the calibration table |
| `analysis/` | training, evaluation, statistics, figures, and the two masked agents |
| `Target/` | a deliberately vulnerable web application, used as a live target |
| `lab/` | a containerised estate for executing techniques against real services |
| `results/` | the JSON record behind every reported number, and the figures |
| `results/telemetry/v5/` | the released ATT&CK-labelled telemetry corpus |
| `results/models/v5/` | the trained policies |

`results/v5_report.md` is generated by `analysis/v5_report.py` and reports every figure
from re-evaluating a saved checkpoint, never from the last point of a training curve.

## The telemetry corpus

`results/telemetry/v5/` holds 31,925 events over 600 episodes, generated by
`analysis/v5_corpus.py` from the ten masked policies, and covers all 45 techniques.
`telemetry.csv` and `telemetry.jsonl` carry the same events, one per row: the episode
and step, the host, its platform and subnet, the log channel and event ID, the technique
with its ATT&CK identifier and tactic, the detection rule that watches it, and the label.
`episodes.jsonl` summarises each episode (the policy, its technique sequence, whether
it reached the objective and whether the defender declared an incident), and
`manifest.json` records how the corpus was generated.

The labels are exact, not inferred: the environment emitted each event while executing a
specific technique. These are constructed records, not captures from real hosts.

## Trained policies

`results/models/v5/` holds the Stable-Baselines3 checkpoints, named by configuration
and seed: `masked_enterprise_s0.zip` is the masked agent on the enterprise estate,
seed 0. A `_b500` or `_b2000` suffix marks a policy trained with that per-episode step
budget instead of the default. The commands that train each one are in
`analysis/run_v5_all.py`.

`results/models/v8_warm/` holds the continued-training runs on the larger estates:
`warm_mid16_s0.zip` is a twelve-host policy trained further on the sixteen-host estate,
`scratch_large20_s0.zip` a policy trained from random weights on the twenty-host estate.
Both are trained by `analysis/v8_warmstart.py`.

## A note on what the success rate is for

A higher attacker success rate is not the product. The product is the telemetry. A policy
that stalls stops emitting, so a defender testing detection coverage against a failing
agent learns nothing about the later stages of a kill chain, because the campaign never
reached them. Nothing here executes against a real network: the environment's actions are
state transitions over an abstract estate, and the only component that touches a live
system is pointed at the vulnerable application in `Target/`, which is included.

## Running it

Python 3.11 with `gymnasium`, `stable-baselines3` and `sb3-contrib`. Training one
configuration takes roughly twelve minutes on a single core.

```
python analysis/v5_train.py --config masked --seed 0
python analysis/v5_report.py
```
